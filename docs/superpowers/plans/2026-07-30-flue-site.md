# flue.sh landing site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** flue.sh live — a manifesto-minimal, single-page landing site that also serves `install.sh`, deployed as a Cloudflare Worker with static assets from the already-authenticated wrangler account, with a workers.dev preview verified before the custom-domain cutover.

**Architecture:** A new top-level `site/` directory with zero dependency on `web/` or Go. Hand-authored `site/public/index.html` + `site/public/style.css`; the only JavaScript is a ~15-line inline copy-to-clipboard enhancement. No framework, no bundler, no build step — the "build" is `cp`. Deployment is an assets-only Cloudflare Worker (`site/wrangler.jsonc`, `assets.directory: "./public"`, no worker script). The canonical installer lives at `scripts/install.sh` (produced by the infra lane); the deploy flow copies it into `site/public/install.sh` at deploy time so there is exactly one source of truth and the page and installer ship as one deploy. Root `Makefile` gains `site-dev` and `site-deploy`; a `deploy-site.yml` workflow keeps CI deploys possible once a `CLOUDFLARE_API_TOKEN` secret exists (optional — local wrangler is the baseline).

**Tech Stack:** Plain HTML5 + CSS. Cloudflare Workers static assets via wrangler v4 (already authed: account `Mail@karngyan.com's Account`, id `0e769bfdf3e92960c59efe29a066005d`). `pnpm dlx wrangler` for all wrangler invocations. A dependency-free Node script (adapted from `web/scripts/generate-icons.mjs`) rasterises the OG image.

## Global Constraints

- No framework, no build step, near-zero JS. The single inline `<script>` is progressive enhancement only — the page is fully functional with JavaScript disabled.
- Total page weight (index.html + style.css + favicon.svg) under **50 KB**, excluding `og.png`.
- The landing copy in Task 1 is **final prose**. Implementers adjust markup and styling, not words.
- `site/` depends on nothing in `web/` or Go (spec: Component boundaries). Brand values (colors, favicon) are *copied* into `site/`, never imported across the boundary.
- The canonical installer is `scripts/install.sh` (infra lane). `site/public/install.sh` is a deploy-time copy, gitignored — two committed copies must never exist.
- Use `pnpm`, never `npm` or `npx`. One-off tools run through `pnpm dlx` (wrangler is `pnpm dlx wrangler@4`).
- wrangler is already authenticated (OAuth, `mail@karngyan.com`). Nothing requires an API token locally.
- **Nothing is deployed to flue.sh until the workers.dev preview is verified** (spec: Testing). The custom domain flip is its own task with its own verification.
- Worker name is `flue-sh` everywhere. Make targets are `site-dev` and `site-deploy` exactly.
- Commit style is conventional with the definite article (`feat(site): ...`, `chore(site): ...`); every commit ends `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- No emojis anywhere in page copy or UI.

**Decided details** (do not relitigate during implementation):

- **Palette:** light manifesto page — background `#ffffff`, body text near-black `#09090b` (zinc-950), secondary text `#52525c`-range zinc, hairlines `rgba(9,9,11,0.1)`. **One accent: amber `#fe9a00`** (matches `web/src/lib/theme.ts` `chrome.accent` and the favicon). The one dark element is the terminal block: background `#09090b`, light text (`#d4d4d8`-range), accent for prompt chevron and cursor. Amber is never used for text on the white ground (it fails contrast there); on the light page it may appear only as a non-text mark or focus ring. Links on white are near-black with underlines.
- **Fonts:** no webfonts, no self-hosting (a font download would dwarf the page). Two system stacks:
  - prose: `ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`
  - code/terminal/wordmark: `ui-monospace, "SF Mono", SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace`
- **www handling:** assets-only Worker cannot redirect, so only the apex `flue.sh` is attached as a custom domain (`routes: [{ pattern: "flue.sh", custom_domain: true }]`). `www.flue.sh → https://flue.sh` is a Cloudflare dashboard Redirect Rule (single redirect, 301, preserve path, plus a proxied placeholder DNS record for `www`) — **out-of-scope manual follow-up**, noted in Task 5. No worker script gets written just to redirect www.
- **OG image:** no svg→png tooling exists on this machine (`rsvg-convert`, `magick`, `convert` all absent; no `sharp`/`resvg` in `web/node_modules`). The repo's own pattern — `web/scripts/generate-icons.mjs`, a dependency-free SDF rasteriser + hand-rolled PNG encoder — is the tooling. Task 2 adapts it to a 1200×630 mark-on-dark-field image (the chevron + cursor mark, no text glyphs; text rasterisation without a font stack is out of reach and hand-drawn letterforms are not worth it). If the rendered card looks broken in preview testing, the fallback is to **remove the `og:image` meta lines entirely** rather than ship a broken card; a real screenshot replaces it after the frontend-polish lane.

**Landing copy (final prose — use verbatim):**

Hero (`#hero`):

- `h1`: **Your terminal, as a browser tab.**
- subline paragraph: **Reachable from any device you own.**
- install block: a `<pre><code id="install-cmd">curl -fsSL https://flue.sh/install.sh | sh</code></pre>` with `<button id="copy-install" type="button" hidden>copy</button>` beside it

`#why` — `h2`: **Why**

> Two apps get used all day: a terminal and a browser. The cost is switching between them. Browsers have tab groups, tab search, splits, session restore, and URL addressing. Terminals have none of it and cannot join in.
>
> flue makes a terminal session a browser tab, so it inherits all of that for free — and makes the same live session reachable from a phone, an iPad, or another laptop.

`#shape` — `h2`: **The shape of it**

> A small Go daemon owns the PTYs and their scrollback. A web app renders them. Closing the tab detaches; the build keeps running. Reattach and it replays what you missed. Attach from two devices and they mirror live — typing on the phone shows up in the laptop's browser, and the phone's 40 columns don't shrink the laptop.
>
> One static binary. No Node, no Python, no toolchain, ever. The CLI is four commands — enable, disable, status, open — and everything after them happens in the browser.

Then the terminal figure (the page's one visual — content fixed, from the parent spec's `flue enable` transcript):

```html
<figure class="terminal" role="img"
  aria-label="A terminal session: flue enable installs the login service, starts the daemon on 127.0.0.1:7717, and opens the UI.">
  <pre>$ flue enable

  ✓ login service installed
  ✓ daemon running on 127.0.0.1:7717
  opening http://127.0.0.1:7717

$ <span class="cursor"></span></pre>
</figure>
```

`#remote` — `h2`: **Reaching it from elsewhere**

> Remote access is opt-in and provider-agnostic. flue has no preferred option; the UI orders providers by what you already have installed.

| provider | what it needs | intermediary |
|---|---|---|
| local | nothing, always on | none |
| Tailscale | Tailscale on each device | none, often direct peer-to-peer |
| Cloudflare | a Cloudflare account, free tier is enough | your own Worker, ciphertext only |
| Cloudflare + your domain | a domain on Cloudflare | Cloudflare |

> Anything that passes through an intermediary is end-to-end encrypted by default — Noise IK, with the daemon's key pinned at pairing — so a relay forwards ciphertext and can never read your shell.

`#principle` — `h2`: **There is no hosted service.**

> No flue account, no flue server, no billing. Every remote path runs on infrastructure you own. flue.sh is docs and downloads, never part of the data path.

Footer: `MIT · © 2026 karnstack` and a link to `https://github.com/karnstack/flue` (link text "GitHub"). The header's GitHub link points at the same URL.

**The inline script (complete — this is all the JS on the page):**

```html
<script>
  // Progressive enhancement: the install command is plain selectable text
  // without JS; this only reveals a copy button.
  (function () {
    var btn = document.getElementById('copy-install')
    var cmd = document.getElementById('install-cmd')
    if (!btn || !cmd || !navigator.clipboard) return
    btn.hidden = false
    btn.addEventListener('click', function () {
      navigator.clipboard.writeText(cmd.textContent.trim()).then(function () {
        btn.textContent = 'copied'
        setTimeout(function () { btn.textContent = 'copy' }, 1500)
      })
    })
  })()
</script>
```

**Design-intent constraints (the frontend-design skill executes within these):**

- Manifesto-minimal: one centered column, max-width ~42rem (~65ch measure), generous vertical rhythm — roughly 6rem between sections on desktop, ~3.5rem at mobile widths; whitespace before dividers, dividers before any card treatment. The table sits on the page background with horizontal hairline rules only.
- Type scale: body 1rem–1.125rem, line-height ~1.6; `h1` fluid via `clamp(2.25rem, 6vw, 3.5rem)`, weight 600 (never 700+), `letter-spacing: -0.02em`; `h2` ~1.375rem, weight 600. The `#principle` h2 may sit larger — it is the thesis statement.
- The terminal figure is the only dark, and the only decorated, element: `#09090b` ground, subtle rounded corners, monospace ~0.875rem, `overflow-x: auto`. Prompt `$` and the cursor in accent `#fe9a00`; the ✓ lines may use accent or the light text — skill's call, but amber appears nowhere else except at most one focus-ring/mark on the light page.
- CSS-only cursor blink, reduced-motion safe:

  ```css
  .cursor { display: inline-block; width: 0.6em; height: 1.1em;
            background: #fe9a00; vertical-align: text-bottom;
            animation: blink 1.2s steps(1) infinite; }
  @keyframes blink { 50% { opacity: 0; } }
  @media (prefers-reduced-motion: reduce) { .cursor { animation: none; } }
  ```

- No JS beyond the inline script. No animation beyond the cursor blink. No icon fonts, no external requests of any kind (self-contained page + favicon).
- `.table-wrap { overflow-x: auto; }` so the three-column table cannot force page-level horizontal scroll at 360px.
- The copy button ships with the `hidden` attribute in markup; only the script reveals it.

### Task 6: CI deploy workflow

**Files:**
- Create: `.github/workflows/deploy-site.yml`

**Interfaces:**
- Consumes: `scripts/install.sh` (in-repo by the time this runs on main); repo secret `CLOUDFLARE_API_TOKEN` (user-provided later, optional — the job skips cleanly without it).
- Produces: automatic flue.sh deploys on pushes to main touching `site/**` or the installer.

**Steps:**

- [ ] **Step 1:** Write `.github/workflows/deploy-site.yml` exactly:

  ```yaml
  # Deploys flue.sh when the site or the installer changes on main.
  #
  # Requires the CLOUDFLARE_API_TOKEN repo secret (Workers Scripts: Edit).
  # The secret is optional: without it the job skips rather than fails —
  # `make site-deploy` from locally-authed wrangler is the baseline path.
  name: deploy-site

  on:
    push:
      branches: [main]
      paths:
        - "site/**"
        - "scripts/install.sh"
        - ".github/workflows/deploy-site.yml"

  permissions:
    contents: read

  jobs:
    deploy:
      runs-on: ubuntu-latest
      steps:
        - uses: actions/checkout@v4

        - name: Check for the deploy token
          id: token
          env:
            CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          run: |
            if [ -n "$CLOUDFLARE_API_TOKEN" ]; then
              echo "present=true" >> "$GITHUB_OUTPUT"
            else
              echo "present=false" >> "$GITHUB_OUTPUT"
              echo "CLOUDFLARE_API_TOKEN is not set; skipping the deploy." \
                   "Local 'make site-deploy' is the baseline."
            fi

        - name: Stage the installer
          if: steps.token.outputs.present == 'true'
          run: |
            test -f scripts/install.sh || {
              echo "scripts/install.sh missing — the infra lane creates it" >&2
              exit 1
            }
            cp scripts/install.sh site/public/install.sh

        - name: Deploy
          if: steps.token.outputs.present == 'true'
          uses: cloudflare/wrangler-action@v3
          with:
            apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
            workingDirectory: site
  ```

- [ ] **Step 2:** Lint the YAML (`pnpm dlx yaml-lint .github/workflows/deploy-site.yml`, or a careful read if that tool misbehaves — the file is 50 lines).
- [ ] **Step 3:** Cross-check consistency with Task 3: the staging step duplicates `make site-deploy`'s copy semantics because `wrangler-action` owns the wrangler invocation; both must reference `scripts/install.sh` → `site/public/install.sh` and nothing else. The guard message matches the Make target's intent.
